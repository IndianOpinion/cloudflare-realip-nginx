# Architecture

This document records how cloudflare-realip-nginx 0.1.0 is built and the
decisions taken on the open questions in [PRD.md](PRD.md), section 13.

## Layout

| Path | Role |
|---|---|
| `bin/cloudflare-realip-nginx` | The tool: one bash script, `set -euo pipefail` |
| `etc/default/cloudflare-realip-nginx` | Config file with every setting commented |
| `systemd/cloudflare-realip-nginx.service.in` | Hardened oneshot unit; `install.sh` fills in the paths |
| `systemd/cloudflare-realip-nginx.timer` | Daily, `RandomizedDelaySec=1h`, `Persistent=true` |
| `cron/cloudflare-realip-nginx.in` | `/etc/cron.d` file; random minute and hour picked at install |
| `cron/periodic-daily.in` | busybox crond (Alpine) `/etc/periodic/daily` script with a random sleep |
| `install.sh` | Install, idempotent re-install, `--uninstall`, `--uninstall --purge` |
| `examples/` | sudoers, log format, include example, offline demo, monitoring check, firewall command printer |
| `tests/` | bats suite, stand-in commands under `tests/helpers/shims`, fixtures, golden files |

The PRD names `test/fixtures/`; the suite lives in `tests/` (with
`tests/fixtures/`) to match the other repositories. Fixture names follow the
PRD, plus a few extras (`v4-slash7.txt`, `v6-slash15.txt`, `v4-shuffled.txt`,
`v4-loopback.txt`, `v6-slash16-floor.txt`).

## Modules inside the script

The script is one file so it installs with one copy. It is split into
sections:

1. **Settings.** Defaults in an associative array, the config file parsed
   line by line (`KEY=value`, optional single or double quotes, no shell
   characters unquoted, unknown keys rejected), then environment variables,
   then flags. Every value is validated before use: paths against a small
   alphabet, URLs against `https://host[:port]/path`, the header against
   `[A-Za-z0-9-]`, commands split into words with no shell syntax. Commands
   are run as argument arrays, never through `eval` or a shell.
2. **Address parsing.** Pure bash parsers for IPv4 and IPv6 CIDRs (decision
   1). They set a canonical text, a fixed-width sort key, the prefix, and the
   address as integers. The IPv6 parser expands `::`, rejects embedded IPv4,
   zone ids and brackets, checks host bits group by group, and prints RFC
   5952 text. Overlap with never-trusted space is a masked compare at the
   shorter of the two prefixes.
3. **Fetch.** One curl call per hop with `--proto =https`, `--tlsv1.2`,
   connect and total timeouts, `--max-filesize`, and `--write-out` for status,
   content type and redirect target. Redirects are followed by the script, not
   by curl, so every hop is checked for HTTPS and the pinned host. curl exit
   codes are sorted into retryable (DNS, connect, timeout, partial transfer,
   receive errors), fatal (TLS and certificate errors, bad URL) and too large.
4. **Validation and render.** Each list is cleaned (BOM, CR, blank lines,
   spaces), checked for non-printable bytes, parsed line by line, deduplicated,
   bounded, sorted, then rendered. The previous snippet is parsed back into
   per-family sets for the shrink guard and the added/removed log.
5. **Install.** Stage, candidate test, backup, rename, full test, restore on
   failure, reload, state.
6. **State, lock, metrics.** A `flock` on `STATE_DIR/lock` (released by the
   kernel when the process dies), a key=value state file written by rename,
   and the optional Prometheus textfile.

## Data flow of an update run

```
config -> lock -> preflight -> recover interrupted run -> hold check
  -> fetch v4 -> fetch v6 -> validate v4 -> validate v6 -> render candidate
  -> compare with live --(same)--> "unchanged", retry pending reload, exit 0
  -> stage in STAGING_DIR -> candidate nginx -t (throwaway config)
  -> backup live to STATE_DIR/previous.conf -> state: in_progress
  -> rename staged over live -> full nginx -t
       fail: restore backup (or delete), nginx -t again, exit 4
  -> state: pending_reload -> nginx -T include check (warning only)
  -> reload (skipped if nginx stopped; failure: exit 5, retried next run)
  -> state: result, last success; metrics; summary line
```

The EXIT trap records the run (time, exit code, result) in the state file for
every run that took the lock, removes temp files and the work directory, and
writes the metrics file. INT, TERM and HUP exit through the same trap.

## Snippet contract

The first line of every snippet is fixed and is what the foreign-file check
(W11) and `--verify` compare against. It must not change within 0.x:

```
# Generated by cloudflare-realip-nginx. Do not edit: changes are overwritten.
```

Section comments `# Cloudflare IPv4 ranges`, `# Cloudflare IPv6 ranges` and
`# Extra trusted addresses (set by the operator)` let the tool read a previous
snippet back. The second line names the tool version, so an upgrade changes
the bytes once and causes one reload.

## Decisions on the open questions

1. **CIDR validation in pure bash, no ipcalc.** One code path on every host,
   no optional dependency whose output format differs between distributions.
   Parsers run without subshells, so validation of both lists costs a few
   milliseconds.
2. **Candidate syntax test.** The candidate is tested with a minimal
   temporary `nginx.conf`: an `events` block and an `http` block that
   includes only the candidate, run as `nginx -t -q -p WORK/nginx/ -c
   WORK/nginx-test.conf`. The throwaway config sets `pid`, `error_log`,
   `client_body_temp_path` and the proxy, fastcgi, uwsgi and scgi temp paths
   (each only when `nginx -V` does not show the module was left out) into the
   work directory, so the test writes nothing outside it and runs without
   root. This runs before anything is installed.
3. **IPv6 is mandatory**, as the PRD says. There is no flag to skip it.
4. **Prometheus textfile metric: optional, off by default.** Set
   `CFRN_METRICS_DIR` to the node_exporter textfile directory. The file
   carries last run time, last exit code, last success time and the range
   count per family, and is written by rename.
5. **Shrink limit default 50 percent.** Any removal needing `--force` would
   page someone for each of Cloudflare's rare, legitimate retirements; a cut
   of more than half is what truncation or a bad mirror looks like.
6. **Temp file in a separate directory, not the include directory.** The
   candidate is written to `CFRN_STAGING_DIR` (default: a hidden directory
   beside the include directory, `/etc/nginx/.cloudflare-realip-nginx` for
   the default output) and then moved into place, so no include glob ever
   sees a partial file. The tool refuses to run if the staging directory is
   the include directory or sits on a different filesystem (compared with
   `stat -c %d`), so the move is still an atomic `rename(2)`, and because it
   is under `/etc/nginx` the file carries nginx's SELinux configuration label
   (lesson 12). The temp name also starts with a dot and does not end in
   `.conf`. This refines PRD W8, which put the temp file in the target
   directory. The integration test also proves open question 6: real nginx
   skips dot files for both `include dir/*` and `include dir/*.conf`.
7. **No JSON cross-check in 0.1.0.** It would be a Cloudflare API call, which
   the PRD rules out.

## Other choices

- **Exit 1 for a bad `--extra-trusted`.** Extra addresses come from the
  operator, so a bad one is a configuration error (exit 1, before any network
  call) rather than a validation failure of fetched data (exit 3). Prefix
  lengths are required, as for the lists (V2).
- **`--verify` exits 1** when any check fails.
- **Dry run and diff take no lock.** They write nothing (no state file, no
  lock file), so the PRD's "not longer than the fetch" is met by not locking
  at all, and they work as non-root (D4). Their log lines go to stderr so
  stdout carries only the snippet or the diff.
- **Non-root runs.** The staged file is `STATE_DIR/staged.conf`, a fixed path,
  so the sudoers rule for `install` needs no wildcard. Restores use the same
  command. On a failed first run without root, where no delete command is
  allowed, the new file is replaced by a header-only snippet that trusts
  nothing.
- **Recovery (W14).** The state file records `in_progress` after the backup
  is written (by rename) and before the snippet is renamed into place. The
  PRD puts the marker before the backup; writing the backup first means a
  crash between the two can never make a later recovery restore an older
  backup. The next run tests first; if the leftover snippet fails, it
  restores the backup and continues the normal run.
- **Extra trusted addresses** skip the prefix floor and the private-space
  checks (V11), but a default route (`0.0.0.0/0`, `::/0`) is still refused
  with exit 1: it would let any client set its own address.
- **Hold (RB3).** A rollback sets `hold_until`. Any update run inside the hold
  logs `held after rollback` and exits 0 without fetching; an expired hold
  warns and is cleared. `--release` clears it.
- **Extra settings not in the PRD table:** `CFRN_STAGING_DIR` (decision 6),
  `CFRN_RETRY_DELAY` (so the backoff is testable), `CFRN_DUMP_COMMAND` (pairs
  with `CFRN_TEST_COMMAND` for custom layouts), `CFRN_SERVICE_NAME`,
  `CFRN_SERVICE_MANAGER` and `CFRN_PID_FILE` (W6 detection),
  `CFRN_METRICS_DIR` (decision 4). All keys are prefixed `CFRN_` so the
  environment overrides cannot collide with unrelated variables.
- **Logging under systemd.** The unit sends stdout to null and stderr to the
  journal; all messages also go through `logger`, so `journalctl -t
  cloudflare-realip-nginx` shows the full history with priorities.
- **Install test seams.** `install.sh` honours `CFRN_SYSTEMD_RUN_DIR`
  (where to look for a running systemd) and
  `CFRN_INSTALL_RUN_SERVICE_COMMANDS=1` (run systemctl and reload even with
  `--destdir`). Both exist for the test suite.

## Tests

`tests/*.bats` cover every case in PRD section 4 with stand-in commands for
curl, nginx, systemctl, sudo, id, logger and mktemp (see
`tests/helpers/shims`). `tests/integration.bats` runs only with
`CFRN_INTEGRATION=1` and uses the real nginx for R6, the dot-file glob
check, an end-to-end W2/W4 and, with `CFRN_INTEGRATION_SYSTEMD=1`, P5 under
the shipped unit's sandbox via `systemd-run`. CI runs shellcheck, the unit
suite, the integration suite in Debian, Ubuntu, Rocky Linux and Alpine
containers, and P5 on the runner host. A weekly job runs `--dry-run --test`
against the live endpoints and opens an issue if it fails.
